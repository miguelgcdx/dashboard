# Pi usage dashboard

## Outcome

Provide a private, local Pi usage dashboard with Tokdash-inspired navigation: Overview, Companies, Agents, Sessions, and Stats. Attribute non-SDD subagent tokens to the actual role and per-call model, alongside parent Pi usage. Preserve the offline file and five-minute user timer; use React + Vite + TypeScript. Production file:// output needs no server; user-approved development runs on loopback with real allowlisted aggregate usage and React hot reload.

## Problem and scope

The existing Pi TUI widget reports only the current session. This dashboard summarizes persisted JSONL sessions across working directories. It never exports prompts, responses, tool arguments, or source paths; the user later explicitly opted in to private display of Pi session names and validated session-header IDs (PUD-17/PUD-19). Source lives in this dedicated project; generated output lives in `~/.local/share/pi-usage-dashboard/index.html`. The existing TUI widget is unchanged. A bar shortcut is out of scope.

## Accounting and safety

- Read `~/.pi/agent/sessions/**/*.jsonl` by default, with optional session-directory override; timestamps of usage events determine local calendar buckets (not filenames or session headers).
- Count assistant and tool-result message usage plus top-level `usage`, `compaction`, and `branch_summary` usage; do not count nested details or reasoning/cacheWrite1h subsets again. Deduplicate copied entries across cloned/forked files using entry identity and event timestamp.
- Cache-read share = `cacheRead / (input + cacheRead + cacheWrite)`; zero denominator displays N/A. Keep output tokens and total cost separate. Week starts Monday; identify local timezone and covered date range.
- Skip malformed/incomplete JSONL lines with a visible warning; flag out-of-range/future timestamps against the local clock. Never infer a trustworthy date from a machine with a wrong clock: make the displayed as-of time explicit.
- Generate self-contained HTML with no network dependencies. The legacy index embeds aggregate usage only; the separately authorized private React snapshot v5 adds explicit Pi session names and validated first-header session IDs on measured-file summaries, not rows. Escape all display text/script payloads and publish atomically with private permissions. In development, the same allowlisted v5 snapshot is allowed only on 127.0.0.1; never expose raw session files, entry/task IDs, prompts, paths, or conversation content. Real Pi header IDs persist across snapshots and may correlate private activity.
- Timer stays under the current user and binds no TCP port. Generated HTML refreshes while open. No credentials, raw session content, source mutation to Pi, or privileged commands.

No OpenCode, SDD agents, quota credentials, cross-machine servers, or unverified estimates. User welcomes a component library when it saves work; prefer an official vanilla-CSS library only after `file://`, CSP, no-network, accessibility, and bundle checks. Keep existing HTML working until the new build and child accounting pass browser/runtime checks. Vite's supported single-entry `iife` output can be embedded with CSS in private HTML; the development server is loopback-only and user-authorized, never a deployment.
